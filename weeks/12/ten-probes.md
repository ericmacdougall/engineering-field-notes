# Ten experiments before trusting active context injection

All cases are synthetic and use disposable services. The local Python fixture covers packet/source/version and service-denial examples only. It does not cover real agents or retrieval.

1. Separate the product approval and data exception in different indexed source classes. Compare literal and prerequisite-aware queries; inspect both source IDs at dispatch.
2. Add distractor approvals for other customers and cohorts. Reject semantically similar but misbound evidence.
3. Move the governing condition through a realistic long prompt for the chosen model and score the proposed action.
4. Update an exception from open to reconciled. Confirm memory invalidation and current-source readback before allowing cutover.
5. Deliver source-change events out of order, then drop one. The dispatch-time source check must determine the verdict.
6. Forge a digest, source URI, owner, version or cohort in a well-formed packet. The host must return `UNKNOWN`.
7. Suppress the specialist's message. A lower service gate must still deny cutover and leave a visible pending task.
8. Send contradictory product, data and security packets in different orders. Authority and escalation must be order-independent.
9. Attempt the same denied effect via local, cloud and delegated tool routes where supported. Use an independent target-state readback.
10. Compare retrieval, long context, improved retrieval and role injection on protected held-out cases. Count critical-fact recall at dispatch, false-green cutovers, false holds, reviewer minutes, recovery cost and ongoing memory maintenance.

The negative-control test deliberately removes the local service gate and must make the test suite fail. If a real system cannot run probes 6–9 without risk, keep it out of autonomous cutover until a safe target is available.
